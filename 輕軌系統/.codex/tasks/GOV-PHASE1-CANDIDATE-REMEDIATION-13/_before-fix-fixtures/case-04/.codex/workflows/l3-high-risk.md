# L3 High Risk

`Classify -> Blueprint allowed paths and Rule layers -> scope_approval -> execution_approval or classified not-required -> controlled implementation -> QA evidence -> unique-session Code/Security/Railway Domain/Compatibility Review -> review_completion -> exact commit manifest and scope validation -> deterministic preapproval gate -> final_commit_approval -> calculated gate`

Any `BLOCKER`, `NEEDS_HUMAN_DECISION`, missing formal review identity, candidate Rule affecting the decision, unsafe environment, unresolved condition or unverifiable rollback produces `NO-GO`. Agent merge and release are forbidden.

For a formal typed Railway Domain Review, the validator must resolve one exact Blueprint review assignment and bind its canonical role, candidate-manifest profile hash, scope, read-only mode, empty write paths, no implementation participation, reviewer run and reviewer session to the review artifact. The assurance is `procedural_role_and_assignment_binding`, not cryptographic or unforgeable identity.

Required evidence is keyed by a globally unique `requirement_id` and must resolve to exactly one `PASS` verdict or one valid evidence artifact. `FAIL`, `NOT_VERIFIED`, and `PASS_WITH_LIMITATION` remain `NO-GO`; `NOT_APPLICABLE` is structurally invalid for Phase 1 required evidence. Phase 1 has no evidence-waiver execution path.

`PASS` cannot carry conditions or decisions. `PASS_WITH_CONDITIONS` requires structured ownership, trigger, completion criteria, resolution evidence, and Reviewer revalidation; unresolved conditions remain `NO-GO`. A claimed resolved condition without evidence or revalidation is structurally invalid. `BLOCKER` requires a finding, and `NEEDS_HUMAN_DECISION` requires a structured human decision record.
