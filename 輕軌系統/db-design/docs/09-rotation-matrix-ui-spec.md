# 周轉件坑位視覺化矩陣 UI 規格

整理日期：2026-06-01

本文件定義周轉件坑位矩陣介面的設計共識，供前端實作與後續討論使用。

---

## 一、矩陣整體結構

```
┌─────────────────────────────────────────┐
│  篩選列（車廂 / 設備類別 / 顯示子件）     │
├────┬──────────────────────────────────────┤
│    │  欄頭：設備類別（sticky）            │
│ 廂 ├──────────────────────────────────────┤
│ 號 │  格子矩陣（車廂 × 坑位）            │
│（s │                                      │
│ ti │                                      │
│ ck │                                      │
│ y）│                                      │
├────┴──────────────────────────────────────┤
│  情境統計列（反映目前篩選結果）           │
└─────────────────────────────────────────┘
```

### 固定行為

- 左側「車廂號」欄：`position: sticky; left: 0`，橫向捲動時保持可見。
- 頂部「設備類別欄頭」列：`position: sticky; top: 0`，縱向捲動時保持可見。

## 二、格子規格

### 顯示密度

| 模式 | 格子顯示 | 觸發 |
| --- | --- | --- |
| 標準（預設） | 色塊 + 設備序號末碼（1 行） + 狀態文字 + 工單號 | 預設 |
| Hover | Tooltip 展示完整序號 / 料號 / 坑位碼 / 工單號 / 更新時間 | 滑鼠懸停 |
| Click | 右側抽屜展開 | 點擊格子 |

### 格子最多顯示 3 行

```
┌──────────────────┐
│ 101-001          │  ← 設備序號末碼
│ 正常上線         │  ← 狀態文字
│ P-001 · 115.05.04│  ← 最近工單號 + 日期
└──────────────────┘
```

> 完整序號（例如 `TETRA-101-001`）從 Hover tooltip 取得，不顯示在格子內。
> 欄頭已標明設備類別，序號前綴不需重複顯示。

## 三、顏色與狀態對照

### 顏色只編碼健康度，細節靠角標

| 顏色 | 語意 | 對應 `asset.current_status` |
| --- | --- | --- |
| 🟢 藍綠 | 在線正常 | 正常上線 |
| 🟡 橘黃 | 空坑待補件 | 坑位有工單但目前無裝件 |
| 🔴 深紅 | 異常 / 急迫 | 故障待拆、驗收退回、逾期 |
| 🟣 紫灰 | 處理中（中性） | 待修、錯修中、外修中、內修中 |
| ⬛ 深灰 | 已報廢 | 報廢 |

### 角標 icon（疊在色塊右上角）

| Icon | 語意 |
| --- | --- |
| 🔧 扳手 | 外修中 |
| ❗ 驚嘆號 | 逾期（可疊在紫灰上 = 處理中但逾期） |
| ✅ 待勾 | 待驗收 |
| 📋 虛線框 | 履歷待補 |

> 顏色與狀態的對應關係存放於 `workflow_option`，前端不 hardcode，從清單取值與對應色碼。

### 圖例列

- 常駐於篩選列右側，可收合。
- **圖例可點選即篩選**：點綠色 → 矩陣只亮在線件，其餘降低透明度。
- 使用色塊 + icon + 文字，不只靠顏色（色盲友善）。

## 四、空坑規格

### N/A（此車無此件）

**不會出現在矩陣中。** 坑位主檔只建立實際存在的坑位，不建 N/A 佔位列。

### 空坑（拆走待補件）

設備被拆走但坑位存在、目前無裝件時，以橘黃色格子顯示，帶出造成該坑空掉的來源工單（C 或 R 皆可）。

```
┌──────────────────┐
│ 101 坑 · 待補件  │  ← 橘黃底
│ C-1150520-D-007  │  ← 來源工單號（C 或 R）
│ 拆出：115.05.20  │  ← 拆出日期
└──────────────────┘
```

點擊 → 抽屜直接帶到關聯工單的「工單與動作」tab。

---

## 五、子件展開

- 頂部篩選列提供「顯示子件」toggle。
- 展開後，父件欄與子件欄用**縮排線或細分隔線**標示從屬關係。
- 展開時頁面自動水平捲到父件欄位置。

---

## 六、右側抽屜（單件詳情）

點擊格子後，從右側滑入固定寬度（420 px）抽屜，矩陣不被推走。

### 抽屜頂部（固定不切換）

```
[ 設備完整序號 ]  [ 大字狀態 + 對應色標 ]
料號 / 料名 · 坑位代碼 · 所屬車廂
```

### 三個 Tab

| Tab | 內容 |
| --- | --- |
| **現況** | 坑位、車廂、倉庫、目前廠商（外修中）、入庫日、累計里程 / 工時 |
| **履歷** | 垂直時間軸（由新到舊）：每筆事件 = 時間 · 事件類型 · from → to · 工單連結 · 操作人 · 備註。資料來源：`asset_event`，依 `seq` 排序 |
| **工單與動作** | 關聯 C/R 工單清單 + 目前 R 工單狀態 + 操作按鈕 |

### 操作按鈕（「工單與動作」Tab 內）

| 按鈕 | 觸發動作 |
| --- | --- |
| 送修 | 新增 `asset_event`（event_type: 送修）+ 更新 `asset` 快照 |
| 修回 | 新增 `asset_event`（event_type: 修回） |
| 驗收合格・回庫 | 新增 `asset_event`（event_type: 回庫） |
| 報廢 | 跳到報廢申請流程 |

> **所有動作只寫 `asset_event`**，`asset` 快照由 trigger 自動回填，不允許前端直接 UPDATE asset。

## 七、情境統計列（底部）

反映**當前篩選條件**的即時統計，不是全隊 KPI（全隊 KPI 在首頁）。

```
本視圖：101–105 廂 × 全部設備
在線 54 件   異常 3 件   待補坑 2 個   外修中 4 件
```

篩選條件改變時即時更新。每個數字可點 → 矩陣自動篩出對應件。

## 九、資料來源對應

| UI 元素 | 資料表 / View |
| --- | --- |
| 矩陣格子 | `v_asset_current_status`（快照） |
| 空坑格子 | `vehicle_position` 無 `current_asset_id` + 關聯工單 |
| 抽屜現況 tab | `asset` + `vehicle_position` + `warehouse` + `vendor` |
| 抽屜履歷 tab | `asset_event`（ORDER BY seq DESC） |
| 抽屜工單 tab | `repair_work_order` JOIN `work_order` |
| 操作按鈕 | INSERT `asset_event` → trigger 回填 `asset` |
| 情境統計列 | 前端即時 aggregate 當前篩選結果 |
