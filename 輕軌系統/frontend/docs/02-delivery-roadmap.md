# 新前端搬移與交付路線圖

更新日期：2026-07-10

## 1. 搬移原則

1. 不在 legacy HTML 繼續開發新功能。
2. 每次只搬一條可完整驗收的垂直流程，不一次複製整頁腳本。
3. 先定 API 與型別，再接正式畫面。
4. 新舊並行期間，legacy 只讀；同一資料只能有一個正式寫入入口。
5. 每一階段都需通過桌面、手機、空資料、錯誤、權限與建置測試。

## 2. 分階段計畫

### Phase 0：前端骨架（已完成）

- React + Vite + TypeScript
- 六個主模組與共用左側導覽
- 共用深色工作型設計
- HashRouter 與單一 HTML 建置

完成標準：六個路由可獨立顯示，legacy 不受影響。

### Phase 1：共用平台層

- 環境設定與 API base URL
- API client、錯誤格式、查詢取消、分頁型別
- loading / empty / error / retry 共用狀態
- 登入身分、角色、路由權限
- 民國年、工單號、日期與狀態格式工具
- TanStack Query 與 React Hook Form + Zod

完成標準：至少能顯示 API 健康狀態、目前使用者與權限不足畫面。

### Phase 2：主檔與共用選項

- 人員、角色、車輛、設備別名、倉庫與儲位
- 儀器、WI、P 模板、表單用料、檢查項目
- Word 範本版本與欄位對應
- 流程選項與狀態顏色

完成標準：後續作業頁的下拉選項全部來自 API，不在前端 hardcode。

### Phase 3：工單清冊與主儀表板

- 工單清冊、篩選、分頁與詳情
- C 工單新增、狀態轉移與完工
- R/J 基本清冊與詳情入口
- 工單事件時間軸
- 主儀表板的工單待辦與異常摘要

完成標準：可用新前端完成一張 C 工單從建立到完工，主儀表板能導向正確篩選結果。

### Phase 4：物料庫存

- 物料清單與詳情
- 庫存摘要、位置與交易紀錄
- 領料、退料、調撥與工單耗用
- 用量趨勢與補料判斷

完成標準：每次過帳都產生交易履歷且 balance 正確，不允許前端直接改庫存數量。

### Phase 5：周轉件管理

- R 單清冊首頁與 R 詳情
- 坑位矩陣與右側現況
- 設備總覽、同型備品、庫房摘要
- 設備序號履歷與坑位履歷
- C 拆裝、R 維修與 `asset_event` 連動

完成標準：可從 C 單追到拆下件、R 單、目前位置與完整設備事件；矩陣不提供正式動作。

### Phase 6：預檢排程資料底層

- 新增排程匯入、排程項目與變更紀錄資料表
- 年度/月度 Excel 匯入預覽與驗證
- 兩年排程產生範圍
- 假日、容量、週期、鏇削與人工覆寫規則服務
- 排程規則自動測試

完成標準：同一輸入資料多次排程結果一致，所有工項都有日期或明確複核原因，不能遺漏。

### Phase 7：預檢月曆與排班規劃

- 月曆總覽
- 日矩陣與拖移/改期
- 簡易排程驗證表與年度切換
- 假日重排、發布與變更紀錄
- 車輛與機廠設備分開檢視

完成標準：24 至 36 天、每日車輛組合、一天一台鏇削、跨月鏇削與設備固定週期都有自動測試與畫面複核提示。

### Phase 8：P 工單作業包與 Word 列印

- 由排程建立 P 工單草稿
- 列印前確認儀器、用料、WI、工作類別與條件選項
- Word 範本版本與欄位套版
- 作業前列印與 print job 履歷
- 預覽資料核對，不重畫正式 Word 版面

完成標準：四個級別輸出與原始 Word 格式一致，欄位、分頁與附件順序可比對。

### Phase 9：預檢完工回填與異常報修

- 待回填清冊與草稿
- 封面、人力、工時、實際用料與處理情形
- 依級別動態檢查項目與量測值
- P1 座椅圖與電磁煞車附件
- 細項異常建立/更新 C 工單
- 完工後封面與附件再次輸出供蓋章

完成標準：必填與標準值驗證正確；每一筆異常都有 C 工單處理或授權原因；完成後更新最新完工日供下一期排程。

### Phase 10：報表、稽核與 legacy 退場

- 維修 KPI、逾期、重複故障、用料與設備報表
- 操作稽核、匯出與權限稽核
- 效能、分頁、錯誤監控與備份復原演練
- 舊功能逐項簽核後移除 legacy 正式入口

完成標準：所有正式工作只從新前端進入；legacy 留存唯讀封存版與移轉紀錄。

## 3. 每階段共同驗收

### 功能

- 正常流程、取消、錯誤、空資料與重複提交都有明確結果。
- 跨模組連結能保留來源與返回位置。
- 正式寫入操作都有確認、成功提示與操作歷程。

### 資料

- API DTO 與 TypeScript 型別一致。
- 列表使用伺服器端分頁與篩選，不一次抓數千筆。
- 日期、時區、民國年與狀態代碼不由畫面自行猜測。

### 介面

- 1440 x 900 與 390 x 844 無重疊或不必要水平溢出。
- 大型矩陣與表格可在自身容器捲動，sticky 欄頭正確。
- 按鈕只呈現可執行命令；檢視頁不混入正式操作。

### 品質

- TypeScript、build 與 `git diff --check` 通過。
- 核心規則有單元測試；跨模組主流程有整合測試。
- 瀏覽器主控台無 error；API 錯誤可被使用者理解。
