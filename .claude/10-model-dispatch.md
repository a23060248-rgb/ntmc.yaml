# 10-model-dispatch.md — 模型調度守則

適用對象：主對話模型（任何等級）。每次要委派工作前照本檔執行。

## 1. 指揮官不下場

主對話（指揮官）的 context 是全 session 最稀缺的資源。以下工作**一律委派 subagent，禁止在主對話直接做**：

- 讀取任何預期輸出 >100 行的檔案或命令輸出
- 掃 repo（grep/glob 找用法、找定義、盤點結構）
- 查網頁 / 讀文件 / 讀 API 說明
- 批次改檔（>3 個檔案的機械性修改）
- 跑長輸出的測試或建置（主對話只收「過/不過 + 失敗摘要」）

主對話只接收：結論、`檔案:行號`、與下一步決策需要的最小資訊。長產物（完整報告、diff、清單）落檔，subagent 回傳路徑。

**例外（可以下場）：** 讀單一小檔（<100 行）做一次性小改；使用者明確要求你親自看某段內容。

## 2. 派工三件套（每次委派缺一即為無效委派）

1. **目標與動機**：要什麼 + 為什麼要（動機讓 subagent 在遇到意外時能做出正確的臨場判斷）。
2. **驗收條件**：可機械檢查的完成判準，動工前寫死。壞例子：「把搜尋做完整」。好例子：「回報所有呼叫 `loadUser()` 的位置，格式為 檔案:行號 + 一行摘要；若超過 30 處，只列前 30 並註明總數」。
3. **回報格式**：明確規定回什麼、多長、長產物落到哪個路徑。

現成模板 → `30-delegation-templates.md`。

## 3. 顯式指定 model 與 effort

**不要憑印象寫型號。** 可用型號以本環境實測為準（見 `00-diagnosis.md`〈本環境實測〉；未填則先跑 `/model` 確認）。

Claude Code 的 subagent 在 `.claude/agents/*.md` 的 YAML frontmatter 用 `model:` 欄位指定，可用值通常為 `haiku` / `sonnet` / `opus` / `inherit`（也可寫完整型號字串）。注意：
- 若型號被組織的 `availableModels` 白名單排除，Claude Code 會靜默改用繼承的模型——所以指定後要在回報裡確認實際使用的型號。
- Subagent 的 extended thinking 設定繼承主對話（v2.1.198 起），沒有逐 agent 的 thinking 開關；要高推理的子任務，確保主對話 thinking 開啟，或在 prompt 內要求逐步推理。

**預設分派表**（首次落地後按實測型號更新 `[待填]`）：

| 任務類型 | 預設模型 | 理由 |
|---|---|---|
| 機械搜尋、glob/grep、格式轉換、批次套用已知模式 | haiku（`[待填：實測型號]`） | 便宜快速，錯了成本低且好驗 |
| 一般實作、重構、研究、審查 | sonnet（`[待填]`） | 本制度的基準線：所有規則都以 sonnet 跑得動為設計前提 |
| 跨模組架構決策、高風險判斷、sonnet 連錯兩次的任務 | opus 或更高（`[待填]`） | 只在升級判準成立時用，見第 5 節 |

## 4. 回報合約（寫進每個委派 prompt 的固定尾段）

Subagent 必須遵守：
- 只回：結論（≤10 行）、關鍵位置（`檔案:行號`）、驗收條件逐條核對結果（過/不過 + 證據一行）。
- 長產物寫檔到指定路徑，回報只給路徑。
- 沒找到／做不到就直說「未找到／未完成 + 原因」，**禁止**用推測填空、禁止回報未經驗證的成功。
- 回報實際使用的模型（防白名單靜默降級）。

## 5. 升降級路徑

- **haiku 級錯一次 → 直接升級**到 sonnet 級重做，不重試。（小模型重試同一難題的期望收益極低。）
- **sonnet 級同一子任務連錯兩次 → 帶完整失敗軌跡升級**到 opus 級：兩次的 prompt、產出、驗收失敗點都附上，讓高階模型看到「什麼已經試過且為什麼失敗」。
- **降級回收**：高階模型解出的做法若可模式化（例：修好一處後其餘 20 處同型），把模式寫成明確步驟，降回 haiku/sonnet 級批次套用。
- **重試上限**：**同一路線**（同模型＋同方法）最多兩輪；第三次前必須換路。升級模型或換方法即算換路，計數歸零。但整件事升到本環境最高可用模型仍失敗 → 停止，帶完整軌跡問使用者，不再自行嘗試。判準 → `20-judgment-rubrics.md`。

## 6. 驗證不自驗

- 驗收一律派 **fresh-context** agent（乾淨 context 的新 subagent，不帶執行過程的推理），只給它：驗收條件 + 受驗物路徑。
- 檔案類：read-back——驗收 agent 實際讀檔，逐條核對驗收條件，引用檔內原文為證。
- 程式碼類：跑測試或實跑，貼命令與輸出摘要為證。不接受「看起來正確」。
- 高風險判斷（會刪資料、動 prod、對外發送、不可逆操作）：加第二意見——另派一個 agent 獨立判斷，或生成多個候選答案後派評審 agent 選優並說明理由。兩意見衝突 → 停下來問使用者。
- 驗收不過 → 回到執行方修，修完重新驗，計入第 5 節的重試次數。
